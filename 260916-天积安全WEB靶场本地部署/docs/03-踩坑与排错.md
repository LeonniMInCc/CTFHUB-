# 03 · 踩坑与排错

本次部署一共踩了 9 个坑，其中 4 个是"不查清楚根本猜不到"的。按出现顺序记录，附定位方法与最终解决。

---

## 坑 1（最要命）中文目录导致 PHP 加载扩展直接崩溃

**现象**：`php.exe -v` 有时能跑，但只要 `php.ini` 里出现任何一行 `extension=xxx`，进程立刻以 `0xC0000005`（ACCESS_VIOLATION，PowerShell 显示 `exit code -1073741819`）退出，**没有任何报错信息**。

**定位过程**（值得记住的二分法）：

```powershell
php.exe -n -v                                  # -n = 不读 php.ini → 正常，说明崩溃与 ini 内容有关
php.exe -c php.ini -v                          # 崩溃 → 锁定 php.ini
# 逐项二分：
#   只写 extension_dir="D:/天积/.runtime/php/ext"（不加载扩展）→ 正常
#   只写 extension=pdo_mysql 且 extension_dir 指向不存在的 D:/x → 崩溃
# 把 php_pdo_mysql.dll 复制到纯 ASCII 的 %TEMP%\ext，再加载 → 正常 ✅
```

结论：**PHP 7.3 从含非 ASCII 字符的绝对路径加载扩展 DLL 时会崩溃**（本机部署目录叫 `天积`）。

**解决**：`extension_dir` 改为相对路径，并保证进程工作目录就是 PHP 目录：

```ini
extension_dir = "ext"
```

```powershell
Set-Location D:\天积\.runtime\php      # ⚠️ 关键：工作目录必须是 PHP 目录
.\php.exe -c .\php.ini -m
```

同理，Apache 必须用 `Start-Process -WorkingDirectory <php目录>` 启动（`start-lab.ps1` 已处理）。
另外两条路都走不通：本机卷未启用 8.3 短名（`dir /x` 看不到短名），`subst` 映射虚拟盘也被系统拒绝。

## 坑 2 `extension=zip` 让 PHP 启动崩溃

**现象**：同一套 `extension=` 列表里，只有加上 `zip` 就崩。

**原因**：该 TS 构建**已把 zip 静态编译进内核**（`php -n -m` 就能看到 `zip`），此时再写 `extension=zip` 会去找并不存在的 `php_zip.dll`，并在这个错误路径上崩溃。本机 `ext\` 目录里确实没有 `php_zip.dll`。

**解决**：删掉 `extension=zip`。逐个扩展排查的顺序（`curl/fileinfo/gd2/mbstring/exif/mysqli/pdo_mysql/pdo_sqlite/sqlite3/openssl/sockets/soap/xmlrpc/xsl/bz2` 全部 OK）：

```powershell
foreach ($e in 'curl','fileinfo','gd2','mbstring','exif','mysqli','pdo_mysql','openssl','soap','zip') {
  $o = & .\php.exe -n -c "$env:TEMP\empty.ini" -d 'extension_dir=ext' -d "extension=$e" -m 2>&1
  "{0,-12} exit={1}" -f $e, $LASTEXITCODE
}
```

## 坑 3 Git 报 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`

**现象**：`git clone / ls-remote` 访问 GitHub 直接失败，隧道其实已建立（代理返回 `200 Connection established`），但 TLS 握手取不到凭据。

**解决**：不改全局配置，单次指定 OpenSSL 后端即可：

```powershell
git -c http.sslBackend=openssl clone https://github.com/HeaSec/HeaSecWebLab.git "D:\天积"
```

> 附带发现：同一环境下 `curl.exe`（schannel）访问任何 HTTPS 都失败，而 Node.js / Python（自带 OpenSSL）完全正常——**下载组件时用 Node/Python 而不是 curl**。

## 坑 4 Apache 起不来：`AH00414: Unable to create child stdin pipe`

**现象**：

```
[mpm_winnt:crit] (OS 5)拒绝访问。: AH00414: Parent: Unable to create child stdin pipe.
[mpm_winnt:crit] AH00419: master_main: create child process failed. Exiting.
```

**原因**：Apache 的 `mpm_winnt` 模块必须借助管道句柄创建子进程；在受限的执行环境（例如被沙箱约束的终端）里，创建带管道句柄的子进程会被系统拒绝（`OS 5 拒绝访问`）。用 `httpd -t` 测试配置是能通过的，因为那时不创建子进程——**报"配置没问题"不等于能启动**。

**解决**：在**普通终端**（双击 `start-lab.cmd`）里启动即可，不受此限制。
判断是否真的起来了：看进程与端口，而不是看命令有没有报错。

```powershell
Get-Process httpd | Select-Object Id,ProcessName
netstat -ano | Select-String ':8080\s+.*LISTENING'
```

## 坑 5 MariaDB 配置文件必须存成 ANSI/GBK

**现象**：`mysql_install_db.exe` 自动生成的 `my.ini` 用编辑器打开是乱码（提示 "invalid UTF-8"）。

**原因**：MariaDB 在 Windows 上按 **ANSI 代码页（简体中文 = 936/GBK）** 读取配置文件；而路径 `D:/天积/...` 含中文，若把配置存成 UTF-8，MariaDB 按 GBK 解析就会得到不存在的路径，服务起不来。

**解决**：写配置时显式指定编码：

```powershell
[System.IO.File]::WriteAllText($path, $cfg, [System.Text.Encoding]::GetEncoding(936))
```

## 坑 6 PowerShell 脚本必须带 UTF-8 BOM

**现象**：脚本在 PowerShell 7 下正常，双击 `.cmd`（内部调用 Windows PowerShell 5.1）后大面积报错：

```
缺少数组索引表达式 / The string is missing the terminator: '.
```

**原因**：Windows PowerShell 5.1 **不会**把无 BOM 的文件当 UTF-8 解析，而是按 ANSI 解读；脚本里的中文（注释与提示语）被拆成非法字节，字符串引号配对被打乱。

**解决**：给 `.ps1` 文件加 UTF-8 BOM：

```powershell
$txt = [System.IO.File]::ReadAllText($f, (New-Object System.Text.UTF8Encoding($false)))
[System.IO.File]::WriteAllText($f, $txt, (New-Object System.Text.UTF8Encoding($true)))
# 校验解析：0 errors 即通过
[void][System.Management.Automation.Language.Parser]::ParseFile($f, [ref]$null, [ref]$err); $err.Count
```

`.cmd` 里同时加 `chcp 65001 >nul`，保证控制台能正确显示中文。

## 坑 7 镜像源要挑：清华源该路径返回 403

**现象**：`mirrors.tuna.tsinghua.edu.cn/mariadb/.../mariadb-10.6.28-winx64.zip` 目录能列出，但直接下载返回 **403**。

**解决**：换源。实测可用：

| 用途 | 可用源 | 备注 |
|---|---|---|
| MariaDB | `mirrors.aliyun.com/mariadb/...`、`archive.mariadb.org/...`、`mirrors.huaweicloud.com/mariadb/...` | 均返回 `206`，支持断点续传 |
| MariaDB | `mirrors.ustc.edu.cn`（返回 200 但无长度）、`mirror.nju.edu.cn`（302） | 可用性一般 |
| MySQL 5.7 | `mirrors.ustc.edu.cn/mysql-ftp/...`（403）、`dev.mysql.com`（403，需带 Referer） | 所以本次直接用 MariaDB 10.6 替代 |
| PHP | `windows.php.net/downloads/releases/archives/`（302 跳转到 `downloads.php.net`） | 用能跟随跳转的下载器 |
| Apache | `apachelounge.com/download/VS18/binaries/...` | 注意：只有当前最新版是真实文件，旧版链接返回 200 但是 2KB 的 HTML 页面（务必核对文件大小！） |

> 校验习惯：下载完先看大小是否合理（Apache 13.9MB / PHP 24.3MB / MariaDB 83.8MB），再比 SHA256。

## 坑 8 初始化数据库时 `smsbypass` 失败

**现象**：首次初始化 59 个子靶场库，58 个成功，日志里有一条：

```
靶场数据库初始化失败: /range/logic/bypass_verify/smsbypass
- SQLSTATE[42S02]: Base table or view not found: 1146 Table 'heasec_common.heasec_sms_simulator' doesn't exist
```

**原因**：短信验证码靶场的初始化 SQL 依赖 `heasec_common` 库的短信表，而该库是在初始化流程的**最后一步**（短信模拟器重置）才创建，存在先有鸡还是先有蛋的顺序问题。

**解决**：全部初始化跑完后再补一次单库初始化：

```powershell
node tools\heasec-api.js /api/heasec/initialize_range.php "range_directory=%2Flogic%2Fbypass_verify%2Fsmsbypass"
```

## 坑 9 初始化接口 ≈2 分钟：客户端超时 ≠ 服务端失败

**现象**：用脚本调 `/api/heasec/reset_database.php` 初始化，客户端 120 秒超时退出，但靶场其实还在建库。

**原因**：初始化要**逐个**执行 59 个子靶场库的 SQL（每个约 2 秒），总时长约 2 分钟；PHP 端有 `output_buffering`，不会在中途输出，客户端断开也不会立刻中断服务端执行。

**解决**：

- 客户端超时设长一点（≥180s），或放到后台跑；
- 判断完成与否**以服务端日志/数据库状态为准**，而不是客户端返回值：

```powershell
Get-Content D:\天积\.runtime\apache\logs\error.log -Tail 5      # 找 "数据库初始化成功"
node tools\heasec-api.js /api/heasec/check_database.php          # initialized: true, range_check 59/59
```

## 排错速查表

| 症状 | 先看这里 | 常见原因 |
|---|---|---|
| 8080 打不开 | `Get-Process httpd`、`netstat -ano \| Select-String 8080` | Apache 没起来（看 `apache\logs\error.log`） |
| 页面报数据库连接失败 | `Get-Process mysqld`、`config\config.json` | MariaDB 未启动 / 账号密码不匹配 |
| `php.exe` 一启动就崩（0xC0000005） | `php.ini` 的 `extension_dir`、工作目录 | 中文绝对路径加载扩展（坑 1）；`extension=zip`（坑 2） |
| Apache 报 `AH00414` | 启动方式 | 受限环境下无法创建子进程（坑 4） |
| MariaDB 启动即退出 | `logs\mariadb-error.log` | 配置编码不是 ANSI/GBK（坑 5） |
| 靶场行为诡异（上传/目录浏览/编码） | Apache `AllowOverride All`、`.htaccess` | 靶场 `.htaccess` 未生效 |
| 某个靶场一直提示未初始化 | `check_database.php` 的 `range_check` | 该库初始化失败，用 `initialize_range.php` 补做（坑 8） |
| 端口冲突 | `my-heasec.ini` 的 `port`、`heasec-httpd.conf` 的 `Listen` | 3306/8080 被别的服务占用 |

---

## 一句话总结

> 在中文目录下用「便携版 Apache + PHP 7.3 + MariaDB」搭这套靶场，**只要记住两件事**：
> ① PHP 的 `extension_dir` 必须是相对路径且工作目录在 PHP 目录；
> ② 所有带中文路径的配置文件（MariaDB 用 GBK、PowerShell 脚本用 UTF-8 BOM）都要处理好编码。
